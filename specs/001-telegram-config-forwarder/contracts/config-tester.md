# قرارداد: آزمون‌کننده کانفیگ (ConfigTester)

> این فایل به **زبان فارسی** نوشته شده است. نام‌ها و امضاها انگلیسی باقی می‌مانند.

## هدف

تعیین قابل اتصال بودن هر کانفیگ با Xray به‌صورت سراسری و مشترک بین مقصدها (مصوب Q4).

## واسط

```python
class ConfigTester(Protocol):
    async def test(self, config: ExtractedConfig) -> TestResult:
        """یک‌بار برای هر کانفیگ یکتا اجرا می‌شود؛ نتیجه بین مقصدها مشترک است."""
```

## قرارداد ورودی/خروجی

- ورودی: کانفیگ معتبرِ حذف‌تکراری‌شده (هرگز کانفیگ تکراری تست نمی‌شود).
- خروجی: `TestResult(status, latency_ms, checked_at, error_class)`؛ `latency_ms` فقط تاخیر **application-level** (اتصال TCP + پاسخ HTTP از طریق پروکسی محلی Xray) است و هرگز ICMP نیست.
- `status=timeout` وقتی رخ می‌دهد که اتصال از آستانه قابل تنظیم (`test_timeout_s`، پیش‌فرض ۱۵ ثانیه) بگذرد.

## قرارداد خطا

- باینری Xray در دسترس نباشد: همه تست‌های چرخه `skipped` + هشدار در لاگ (افت تدریجی، FR-012 هم‌ارز).
- خطای غیرمنتظره یک کانفیگ: `failed` با `error_class` ثبت می‌شود و چرخه ادامه می‌یابد.
- نتیجه `failed`/`timeout` یعنی مسیریابی به مقصد قرنطینه (FR-014).

## پیاده‌سازی

- `XrayConfigTester`: تولید پیکربندی موقت Xray از روی لینک کانفیگ، اجرای زیرفرایند `xray run` با inbound محلی، آزمون HTTP، توقف و پاک‌سازی؛ حد هم‌زمانی قابل تنظیم برای صرفه‌جویی منابع.
