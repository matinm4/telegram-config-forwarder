# معماری سامانه (Architecture)

## نمای کلی

خط لوله ۱۳ مرحله‌ای در `src/pipeline.py` هماهنگ می‌شود. هر مرحله ماژول مستقل با واسط مشخص است (اصل ماژولار بودن قانون اساسی).

```text
Source → Fetch → Parse → Extract → Normalize → Deduplicate
  → Clean/filter → Detect location → Test → Measure latency
  → Distribute → Format → Send → Persist execution state
```

انشعاب قرنطینه بعد از Test رخ می‌دهد و به Distribute برمی‌گردد. هیچ مسیری به قبل از Deduplicate برنمی‌گردد (تضمین صفر تست تکراری).

## کامپوننت‌ها

| ماژول | مسئولیت | نکته |
|-------|---------|------|

| `providers/bot_sender.py` | ارسال اصلی Bot API | طبقه‌بندی retryable/permanent |
| `providers/telethon_sender.py` | ارسال جایگزین | انتخاب خودکار با آستانه |
| `extraction/` | یافتن لینک، تشخیص پروتکل (۸ پروتکل v1)، ساخت رکورد + هش دقیق | تطبیق تکراری دقیق بدون نرمال‌سازی |

| `testing/xray_tester.py` | اجرای Xray، probe از طریق پروکسی محلی، تاخیر application-level | باینری غایب یعنی `skipped` |
| `distribution/distributor.py` | استراتژی‌ها + مکان‌نمای پایدار | قرنطینه هرگز از این مسیر انتخاب نمی‌شود |

| `logging_setup.py` | لاگ + ماسک اسرار | آزمون واحد redaction دارد |

## تصمیم‌های معماری (خلاصه ADR)

1. **اسکرپ اول، Telethon دوم** — بدون اعتبار برای عمومی کافی است.
2. **ارسال اصلی Bot API، جایگزین Telethon** — سادگی + پوشش خرابی.
3. **Xray باینری پین‌شده + زیرفرایند** — سریع‌ترین نصب تکرارپذیر در CI.
4. **تاخیر فقط application-level** — ICMP در رانرهای Azure مسدود است.
5. **وضعیت در خود مخزن** — ساده و حسابرسی‌پذیر در رانر موقت.
6. **حذف تکراری دقیق قبل از تست + نتیجه مشترک** — صفر هزینه تکراری.
7. **GeoIP آفلاین پیش‌فرض** — بدون وابستگی و بدون افشا.
8. **تک‌پروژه Python ناهمگام** — ایزولاسیون خطا با حداقل پیچیدگی.

جزئیات کامل تصمیم‌ها: `specs/001-telegram-config-forwarder/research.md` و `plan.md`.

## انحراف‌های خرد ثبت‌شده (یافته F4)

مواردی که در plan با این دقت نیامده بودند ولی برای اجرای FRها لازم شدند:

- `consecutive_failures` در وضعیت: شمارنده خطاهای پیاپی هر منبع/فرستنده برای آستانه `fallback.after_failures` (‏FR-025).
- `Destination.rules`: قوانین پالایش مستقل هر مقصد که روی پیام نهایی همان مقصد اعمال می‌شود (T049).
- هلپر `run_with_retry` در `providers/base.py`: سیاست تلاش مشترک FR-033 برای هر دو فرستنده.
- معنای `per_destination`: همه مقصدهای فعال دریافت می‌کنند و هر کدام قوانین خودش را اعمال می‌کند (معادل broadcast قانون‌مند).
