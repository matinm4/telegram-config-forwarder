پستچی خودکار کانفیگ‌های تلگرام

سیستمی که هر ۳ ساعت کانال‌های منبع را می‌خواند، لینک‌های تازه را بیرون می‌کشد، تمیز و تست می‌کند و در کانال‌های تو منتشر می‌کند — روی سرور گیت‌هاب، بدون روشن ماندن هیچ کامپیوتری.

۳ ساعتهر چرخه، خودکار
۱۳مرحله خط لوله
۸۲تست خودکار
۰سرویس لازم

به زبان ساده

خیلی از کانال‌های تلگرام لینک‌های اتصال (کانفیگ‌های VPN) را پخش‌به‌پخش منتشر می‌کنند. این پروژه یک ربات «جمع‌کن و پخش‌کن» است که آن لینک‌های پراکنده را از کانال‌های منبع برداشته و مرتب و سالم در کانال تو می‌گذارد.

تشبیه: مثل یک پستچی است که هر ۳ ساعت سر می‌رسد، نامه‌های تازه را از چند خانه برمی‌دارد، پاکت‌های تکراری و بیاعتبار را دور می‌ریزد، سالم‌ها را امتحان می‌کند، و فقط سزاوارها را در صندوق خانه تو می‌گذارد.

هر چرخه چه می‌کند؟

خط لوله ۱۳ مرحله‌ای — از «گرفتن» تا «فرستادن». روی هر مرحله کلیک کن:

  • ۱Source — خواندن لیست کانال‌های منبع
  • ۲Fetch — گرفتن پست‌های جدید هر کانال
  • ۳Parse — ساختاردهی به پست خام
  • ۴Extract — بیرون کشیدن لینک کانفیگ
  • ۵Normalize — یکدست‌سازی فرمت
  • ۶Deduplicate — حذف تکراری‌ها (هش)
  • ۷Clean — حذف امضا و تبلیغ
  • ۸Location — تشخیص شهر سرور
  • ۹Test — تست اتصال با Xray
  • ۱۰Latency — اندازه‌گیری تاخیر
  • ۱۱Distribute — پخش بین مقصدها
  • ۱۲Format — قالب‌بندی پیام
  • ۱۳Send — ارسال و ذخیره وضعیت
  • ⇢انشعاب قرنطینه: تست‌ناموفق‌ها به کانال جدا می‌روند

قابلیت‌های کلیدی

چند منبع، چند مقصدهر تعداد کانال منبع و مقصد؛ هر کدام قانون و شناسه مستقل.
ضد تکراری قطعیوضعیت آخرین پست‌ها و هش کانفیگ‌ها روی گیت‌هاب نگه داشته می‌شود؛ حتی با اجرای مجدد، چیزی دو بار ارسال نمی‌شود.
تست واقعی اتصالهر کانفیگ با Xray واقعاً امتحان می‌شود؛ تاخیر واقعی مسیر نمایش داده می‌شود.
کانال قرنطینهکانفیگ‌های مریض در کانال جداگانه می‌نشینند، نه قاطی کانفیگ‌های سالم.
مسیرهای جایگزین خودکاراگر اسکرپ یا Bot API خراب شود، سیستم خودش به Telethon سوئیچ می‌کند.
لاگ بدون رازتوکن و نشست هیچ‌جا چاپ نمی‌شوند؛ حتی در لاگ‌ها ماسک‌اند.

چطور اجرا می‌شود؟ (بدون سرور)

قلب ماجرا این است که هیچ سروری لازم نیست. فایل .github/workflows/forwarder.yml هر ۳ ساعت در زیرساخت رایگان GitHub Actions اجرا می‌شود، یک چرخه کامل انجام می‌دهد، و وضعیت را دوباره در همان مخزن کامیت می‌کند. تو می‌توانی هر وقت خواستی از تب Actions دکمه Run workflow را بزنی.

یعنی: کامپیوترت می‌تواند خاموش باشد و تو خواب باشی — پستچی سر ساعت می‌آید و کارش را می‌کند.

اسرار و امنیت

هیچ توکنی در مخزن نیست. همه از GitHub Secrets خوانده می‌شوند:

رازلازم؟کاربرد
BOT_TOKENبلهارسال پیام از طریق ربات
API_ID / API_HASH / SESSION_STRINGاختیاریمسیر جایگزین Telethon (کانال خصوصی / خرابی مسیر اصلی)
MAXMIND_LICENSE_KEYاختیاریدانلود پایگاه GeoLite2 برای تشخیص شهر

کدها چه شکلی‌اند؟

هر مرحله خط لوله یک ماژول مستقل است با واسط مشخص (پایتون ناهمگام، اعتبارسنجی با pydantic):

فایلمسئولیت
src/main.py · pipeline.pyنقطه ورود و هماهنگ‌کننده ۱۳ مرحله
src/config_loader.pyخواندن و اعتبارسنجی config.yaml؛ خطاهای فارسی؛ اسرار فقط از محیط
src/providers/دریافت (scrape / telethon) و ارسال (bot / telethon)
src/extraction/پیدا کردن لینک، تشخیص پروتکل، ساخت رکورد + هش
src/filtering/ · location/ · testing/حذف تبلیغ، GeoIP آفلاین، تست با Xray
src/distribution/ · formatting/پخش چرخشی و قالب پیام هر مقصد
src/persistence/state/state.json اتمیک: آخرین شناسه‌ها، هش‌ها، مکان‌نما
tests/۸۲ تست واحد/قرارداد/یکپارچهگی، بدون شبکه

چرا این شکلی ساخته شده؟

اسکرپ اول، Telethon دومبرای کانال عمومی اعتبار لازم نیست؛ مسیر دوم فقط برای شرایط خاص.
Bot API اول، Telethon دومسادگی در حالت عادی + پوشش خودکار خرابی.
Xray پین‌شده با چک‌سامهر اجرا دقیقاً همان باینری معتبر را نصب می‌کند؛ تکرارپذیر و امن.
وضعیت در خود مخزنstate.json کامیت می‌شود؛ ساده، قابل حسابرسی، بدون دیتابیس.
حذف تکراری قبل از تستکانفیگ تکراری هرگز تست نمی‌شود؛ صفر هزینه اضافه.
GeoIP آفلاینبدون سرویس خارجی، بدون افشای IP در سرویس‌های شخص ثالث.

می‌خواهی امتحانش کنی؟

راه محلی (برای توسعه)پایتون ۳.۱۲، نصب requirements.txt، تنظیم متغیر BOT_TOKEN و اجرای python -m src.main --config config.yaml --once
