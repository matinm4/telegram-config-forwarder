# راهنمای فارسی مدیریت پیکربندی

این راهنما هر گزینه فایل `config.yaml` را توضیح می‌دهد: چه کاری انجام می‌دهد، مقادیر مجاز چیست و چگونه تغییرش دهید. برای شروع، از `config.example.yaml` کپی بگیرید:

```bash
cp config.example.yaml config.yaml
```

> **امنیت:** هیچ secret (توکن، نشست، کلید) هرگز در این فایل نوشته نمی‌شود. همه اسرار فقط از متغیر محیطی (در تولید: GitHub Secrets) خوانده می‌شوند.

## متغیرهای محیطی (اسرار)

| متغیر | الزامی؟ | کاربرد |
|-------|---------|--------|
| `BOT_TOKEN` | بله | ارسال از مسیر اصلی Bot API |
| `API_ID` / `API_HASH` / `SESSION_STRING` | فقط برای مسیر دوم Telethon | دریافت دوم و ارسال جایگزین |
| `MAXMIND_LICENSE_KEY` | فقط اگر موقعیت فعال است | دانلود پایگاه GeoIP در گردش کار |

## `version`

نسخه اسکیمای پیکربندی. فعلاً همیشه `1`.

## `schedule.interval_hours`

فاصله اجرای دوره‌ای به ساعت (پیش‌فرض `3`). توجه: زمان‌بندی واقعی در `.github/workflows/forwarder.yml` (cron) هم باید همین مقدار باشد.

## `sources` (فهرست منابع)

هر مورد:

| کلید | معنا | مقادیر |
|------|------|--------|
| `id` | شناسه پایدار داخلی (در وضعیت ذخیره می‌شود) | متن یکتا، مثل `src1` |
| `username` | نام کاربری کانال (با یا بدون `@`) | مثل `example_channel` |
| `enabled` | فعال/غیرفعال بودن این منبع | `true` / `false` |
| `fetch_mode` | روش دریافت | `scrape` (پیش‌نمایش عمومی بدون اعتبار، اولویت اول) / `telethon` (با اعتبار، برای خصوصی) / `auto` (اول اسکرپ، در صورت خطای قابل تلاش مسیر دوم) |
| `proxy` | پروکسی اختیاری همین منبع | `null` یا مثل `socks5://127.0.0.1:10808` |

## `destinations` (فهرست مقصدها)

| کلید | معنا | مقادیر |
|------|------|--------|
| `id` | شناسه پایدار داخلی | متن یکتا |
| `chat` | نشانی چت/کانال مقصد | مثل `@my_channel` |
| `enabled` | فعال بودن | `true` / `false` |
| `sender` | روش ارسال | `bot_api` / `telethon` / `auto` (اول اصلی، سپس جایگزین) |
| `quarantine` | آیا این مقصد قرنطینه است؟ | حداکثر **یک** مقصد قرنطینه فعال؛ کانفیگ ناموفق در تست به آنجا می‌رود. اگر هیچ قرنطینه‌ای تعریف نشده باشد، کانفیگ ناموفق حذف و در لاگ ثبت می‌شود. |

## `distribution.strategy`

روش تقسیم کانفیگ‌ها بین مقصدها: `round_robin` (پیش‌فرض، چرخشی با مکان‌نمای پایدار) / `broadcast` (همه به همه مقصدها) / `balanced` / `source_based` / `per_destination`.

## `filtering`

| کلید | معنا |
|------|------|
| `enabled` | روشن/خاموش بودن کل پالایش |
| `rules` | فهرست قوانین؛ هر قانون `type` (`exact` عبارت دقیق / `regex` الگو)، `pattern`، `scope` (`text`/`caption`/`both`) و `enabled` دارد. الگوی خراب به‌صورت امن نادیده گرفته می‌شود. |
| `append_destination_username` | افزودن نام مقصد به انتهای پیام (`true`/`false`) |

## `location`

| کلید | معنا |
|------|------|
| `enabled` | روشن بودن تشخیص موقعیت |
| `fallback_display` | متن جایگزین وقتی موقعیت تشخیص داده نشد (پیش‌فرض `Unknown`) |

## `testing`

| کلید | معنا |
|------|------|
| `enabled` | روشن بودن آزمون اتصال |
| `timeout_s` | آستانه timeout به ثانیه (پیش‌فرض `15`، حداکثر ۳۰۰)؛ عبور از آن `timeout` محسوب می‌شود |
| `xray_version` | نسخه پین‌شده باینری Xray (مثل `v26.3.27`) |

نکته: «تاخیر» نمایش‌داده‌شده همیشه تاخیر application-level (اتصال از طریق خود کانفیگ) است، نه ping شبکه‌ای.

## `fallback`

| کلید | معنا |
|------|------|
| `source_fallback_enabled` / `sender_fallback_enabled` | فعال بودن مسیر جایگزین برای دریافت/ارسال |
| `after_failures` | گذر به مسیر جایگزین پس از N خطای پیاپی (پیش‌فرض `2`، بین ۱ تا ۱۰) |

## `retry`

| کلید | معنا |
|------|------|
| `max_attempts` | حداکثر تلاش برای خطای قابل تلاش (پیش‌فرض `3`، بین ۱ تا ۵) |
| `backoff_s` | فاصله نمایی بین تلاش‌ها به ثانیه (پیش‌فرض `[1, 2, 4]`) |

## `concurrency`

| کلید | معنا |
|------|------|
| `source_limit` | حداکثر منابع هم‌زمان (پیش‌فرض `4`، بین ۱ تا ۱۶) |
| `test_limit` | حداکثر تست‌های Xray هم‌زمان (پیش‌فرض `4`، بین ۱ تا ۱۶) |

## `logging.level`

سطح لاگ (`DEBUG`/`INFO`/`WARNING`/`ERROR`). در هیچ سطحی secret چاپ نمی‌شود.
